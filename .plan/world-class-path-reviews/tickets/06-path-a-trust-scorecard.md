# Path A human-trust scorecard

## Question

How do we **score** a Path A one-pager in a cheap test loop — concrete pass/fail or rubric items for “useful not long” / trusted in &lt;2 minutes — so prototypes and later implementation can be judged the same way?

## Answer

**Method:** hard gates only — every gate YES, or the sample **fails**. This scores the **Path A feedback one-pager**, not the length of the source lesson plan. Worked example: [06-trust-scorecard-example](../assets/06-trust-scorecard-example.md). Grounded by [Curriculum feedback form research](./09-curriculum-feedback-form-research.md).

### Locked gates (all must pass)

| Gate | Plain English |
|------|----------------|
| **C1** | Top gaps come first; each Top gap has **Why** + **Improve** |
| **C2** | Feedback page is skimmable in ~**2 minutes** / ~**one page** (source lesson plan may be longer) |
| **C3** | Improve = auditor cues only (add/clarify) — never drafts the lesson |
| **C4** | No essays, no classroom observation / teaching scores, no invented content |
| **X5** | Section order matches locked one-pager (gaps → working → Hunter → evidence) |
| **X6** | Strong / Adequate / Weak only on **PRESENT** (never on MISSING/MISALIGNED) |
| **X7** | Evidence pointers stay short (no table dumps / cite bleed) |
| **G8** | At most **3** Top gaps (priority-first; research adapt) |

**Prototype status:** the locked one-pager prototype already passes this set (3 Top gaps).
