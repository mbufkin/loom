# Curriculum-First Pipeline Correction Plan

## Objective
Decouple the calendar generation from the document placement logic. The calendar is now a **provisional hypothesis** generated by `ingest.py`, which `place.py` must validate, correct, or expand based on the actual volume and type of evidence documents.

## Phase 1: Expand Document Taxonomy (`audit_lib.py`)

**Goal:** Allow models to classify documents by their *actual classroom function* rather than just their format. This prevents false gap reports (e.g., flagging a "missing exit ticket" on a day that is actually a "Project Day").

### Changes to `audit_lib.py`

1.  **Update `DOC_TYPES` Enum/List:**
    Add the following new types to the allowed classification list:
    ```python
    # Existing
    LESSON_PLAN = "lesson_plan"
    LESSON_CONTENT = "lesson_content"
    EXIT_TICKET = "exit_ticket"
    QUIZ = "quiz"
    ANSWER_KEY = "answer_key"
    RUBRIC = "rubric"
    WORKSHEET = "worksheet"
    
    # NEW ADDITIONS
    PROJECT_WORK = "project_work"       # Student artifacts, drafts, code
    PRESENTATION = "presentation"       # Slides, speaker notes, video scripts
    GAME_ACTIVITY = "game_activity"     # Game boards, rule sheets, cards
    LAB_ACTIVITY = "lab_activity"       # Lab sheets, data tables, safety guides
    FLEX_DAY = "flex_day"               # Catch-up, independent study, free reading
    OTHER = "other"
    ```

2.  **Update `classify_doc_type()` Function:**
    Modify the prompt sent to the `analyst` model (localhost:8080).
    
    *   **Old Prompt Context:** "Classify this document as one of: [lesson_plan, worksheet, etc.]"
    *   **New Prompt Context:** 
        ```text
        Classify the primary classroom function of this document. 
        Use these categories: lesson_plan, lesson_content, exit_ticket, quiz, answer_key, rubric, worksheet, project_work, presentation, game_activity, lab_activity, flex_day, other.
        
        If the document is a student output (e.g., a finished project, a slide deck they presented), classify as project_work or presentation.
        If the document is a game or lab, classify accordingly.
        ```

## Phase 2: Provisional Calendar & Smart Gap Reporting (`place.py`)

**Goal:** `place.py` no longer treats `calendar.yaml` as immutable. It treats it as a draft. It will report two types of issues:
1.  **Calendar Corrections:** The calendar is wrong (e.g., too few days, wrong roles for a day).
2.  **Content Gaps:** The curriculum is genuinely missing required evidence for a corrected day.

### Changes to `place.py`

1.  **New Function: `validate_and_adjust_calendar(calendar_data, evidence_units)`**
    *   **Input:** The provisional `calendar.yaml` and the list of `evidence_units` (documents with their new `doc_type`).
    *   **Logic:**
        *   Iterate through each day in the calendar.
        *   Count documents assigned to that day.
        *   If a day has `expected: ["lesson_plan"]` but contains 5 `project_work` documents, flag this as a **Calendar Correction**.
        *   If the total number of documents significantly exceeds the number of days (e.g., 27 docs in 2 days), flag that the calendar needs expansion.
    *   **Output:** A list of `correction_suggestions` (e.g., "Day 3: Change expected role from 'lesson_plan' to 'project_work'").

2.  **Update Function: `build_gap_report(calendar_data, evidence_units)`**
    *   **Step 1: Apply Corrections.** Before checking for gaps, apply the `correction_suggestions` to create a `corrected_calendar`.
    *   **Step 2: Check for Gaps on Corrected Calendar.**
        *   For each day in `corrected_calendar`, check if the required `expected` roles are present in the evidence.
        *   If a role is missing, it is a **Content Gap**.
    *   **Step 3: Check for Overflows.**
        *   If a day has more documents than can reasonably fit (heuristic: >5 docs for a single lesson), suggest splitting the day or adding a new day.

3.  **Update Prompt for `analyst_place` (localhost:8080):**
    *   **Old Prompt:** "Place these documents into the calendar slots. Report gaps."
    *   **New Prompt:**
        ```text
        The calendar below is a PROVISIONAL ESTIMATE. It may be incorrect.
        
        1. Review the documents and their types (e.g., project_work, presentation).
        2. If a day's "expected" role does not match the documents assigned to it, suggest a correction.
        3. If there are too many documents for one day, suggest adding new days.
        4. Only report a "Content Gap" if the corrected calendar still lacks required evidence.
        
        Calendar:
        {calendar_yaml}
        
        Evidence:
        {evidence_json}
        ```

4.  **Update Prompt for `verifier_place` (localhost:30000):**
    *   **New Prompt:**
        ```text
        Verify the proposed calendar adjustments.
        - Did the analyst correctly identify that a "Project Day" should not require an "exit_ticket"?
        - Are the suggested new days justified by the volume of evidence?
        - Return the final corrected calendar YAML and a list of any remaining content gaps.
        ```

## Phase 3: Orchestrator Updates (`run-all-units.py` & `run_project.py`)

**Goal:** Ensure the new logic flows correctly.

1.  **`run-all-units.py`:**
    *   No major changes needed, but ensure it passes the `evidence_units` (with new `doc_type`) to `place.py`.

2.  **`run_project.py`:**
    *   Add a step after `ingest.py` to print a summary of the provisional calendar's assumptions (e.g., "Ingested 27 docs, provisional calendar has 2 days. Expecting corrections.").

## Phase 4: Schema Changes (`calendar.yaml`)

**Goal:** Support the new provisional nature of the calendar.

1.  **Add `status` field to each day:**
    ```yaml
    days:
      - day: 1
        date: "2023-09-01"
        expected: ["lesson_plan", "exit_ticket"]
        status: "provisional"  # NEW: Can be "provisional", "corrected", "verified"
        notes: ""              # NEW: For analyst/verifier comments
    ```

2.  **Add `corrections` field to the root calendar:**
    ```yaml
    corrections:
      - day: 1
        original_expected: ["lesson_plan"]
        corrected_expected: ["project_work"]
        reason: "Documents are student project artifacts, not lesson plans."
    ```

## Execution Order

1.  **Modify `audit_lib.py`**: Add new `DOC_TYPES` and update `classify_doc_type()` prompt.
2.  **Modify `place.py`**: Implement `validate_and_adjust_calendar()` and update `build_gap_report()` to use the two-tier gap reporting (Corrections vs. Gaps). Update prompts for analyst/verifier.
3.  **Update `calendar.yaml` schema**: Add `status` and `corrections` fields (backward compatible if missing).
4.  **Test**: Run `run_project.py` on a sample unit with 27 documents. Verify that:
    *   The calendar expands to accommodate the volume.
    *   Days with `project_work` do not report missing `exit_ticket` gaps.
    *   The gap report clearly distinguishes between "Calendar was wrong" and "We are missing evidence."

## Rollback Plan

If the new gap report is too noisy:
1.  Revert `audit_lib.py` to old `DOC_TYPES`.
2.  Revert `place.py` prompts to the old "treat calendar as authoritative" logic.
3.  Remove `status` and `corrections` fields from `calendar.yaml`.
