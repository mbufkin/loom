01

The one-paragraph version

You asked whether the structure is set. It nearly is — the routing layer is genuinely solid. But when I ran each pipeline stage individually, two of the ten crash on import. They are wrapped in try/except, so the pipeline logs a warning and reports success. One of the two is the stage that grades every non-lesson document. Because it never runs, the quality gate that is supposed to stop a unit being called "Strong" when its quizzes have no answer keys can never fire.

Meanwhile Paths B–H compute exactly that missing information, in more detail than the broken stage ever did, and write it to disk where nothing reads it. So this is not a choice between two competing designs. It is one working scorer with no consumer, and one consumer whose scorer is gone.

Why this blocks tuning

Tuning means adjusting how documents get rated and watching the numbers move. Right now the richest ratings you have reach no report, and the report has a hole where they should be. You would be tuning a signal that nothing consumes, against a dashboard that cannot respond to it.

Why nobody noticed

All three rungs are called inside a best-effort band in run_project.py. A crash becomes a one-line warning in a long log, and the run still reports success:

run_project.py:410
if ARTIFACT_RUNG.is_file():
    try:
        run_step(ARTIFACT_RUNG, ["--project", args.project])
    except Exception as e:
        log(f"WARN: artifact-rung skipped: {e}")   ← swallowed, run continues

Nothing afterwards asserts that ARTIFACT-RUNG.json exists. There is no ARTIFACT-RUNG.json anywhere on disk in this repository — not in any project, not in any E2E run. The stage has produced nothing for a long time.

Where the scorer went

artifact_scorers.py was committed in a13d3a3 "Paths B/C: curriculum-agnostic artifact review + UI", along with working ARTIFACT-RUNG.json outputs for three projects. It is not in HEAD and there is no commit that records deleting it. The only trace left on disk is a stale bytecode cache dated 23 July 2026. That signature — a file present in an old commit, absent from HEAD, with no deletion commit — is what a history rewrite looks like, and there is a plausible candidate in the log: 7a3252b "Polish public Loom for a cared-for first impression". The same commit's ARTIFACT-RUNG.json outputs are also gone.

The consequence, precisely

unit_rung.py decides a unit's band. Being "Strong" requires not metrics.get("has_artifact_gap"). That flag comes from _unit_artifacts(), which is explicitly written to return a gap-free block when the artifact rung is absent. So with the rung dead, the flag is always False and the gate is inert — a unit can be rated Strong while containing 25 quizzes with no answer key.

05

What I recommend, and why

When I first mapped this I framed it as a design choice between two scorers. That framing was wrong, and the correction matters: there is no live competitor. One system works and has no consumer; the other has a consumer and no working code. That collapses the decision.

Recommendation: make Paths B–H the single non-lesson scorer

Replace the body of artifact_rung.py so that instead of re-deriving presence from a second spec format, it reads path_*/findings.json and rolls them up per unit into the ARTIFACT-RUNG.json shape unit_rung.py already expects.

The consumer contract is already documented and stable (artifact_count, gate_pass_count, deterministic_gaps, roles). You are filling an empty socket with a better plug — not choosing between two designs, and not rewriting the reporting layer.

Why not the alternatives

Restore artifact_scorers.py from commit a13d3a3 no Recoverable, and it would light the dashboard back up. But it reinstates the weaker of two scorers and permanently locks in two spec formats for the same job — the exact thing you would then have to tune twice.

06

The checks that would have caught this

This is the part that matters more than the individual bug. The bug is cheap to fix. The reason it survived for weeks is that nothing in the system asserts that a stage produced anything.

  1. Import-check every stage in CI

    A three-line test that imports all ten pipeline modules would have caught both failures the day they appeared. This is the single highest-value check on the list and takes minutes to write.

  2. Assert expected artifacts after a run

    A full run should declare what it produces and fail if a file is missing. Today a stage can vanish and the run still says success.

  3. Make "best-effort" mean something narrower

    The try/except band is appropriate for a stage that needs a model that might be offline. It is not appropriate for an ImportError, which is always a bug. Let import and syntax errors through; swallow only what is genuinely optional.

  4. Freeze the findings contract

    Write a schema for path_*/findings.json, make Path A conform to it — today it alone lacks status, lens, checklist and inventory — and validate at write time.

  5. Golden-pin the findings

    This is what makes the tuning phase reviewable. With findings pinned, changing a keyword in assessment.yaml produces a readable diff — "23 documents moved from MISSING to PARTIAL" — instead of an invisible shift. tools/snapshot_findings.py already does this for Layer 1 and isn't in CI; extend the pattern and normalize the generated_at timestamp.

Already verified working

Routing is deterministic — I re-ran route plus paths on a lab project and findings.json was byte-identical, with the route map differing only in its timestamp. All eight paths genuinely run in production. Absent document types degrade to skipped rather than erroring, confirmed across six workspaces. The router cascade has explicit precedence with fourteen tests pinning it. Paths B–H all emit the same nine top-level keys. The offline suite is green at 84 assertions and now gated in CI.
